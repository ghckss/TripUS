# Figma AI 디자인 개선 프롬프트

현재 TripUS Figma 파일에서 작업하며 아래 프롬프트를 1번부터 순서대로 입력한다. 기존 디자인의 따뜻한 베이지·코랄·딥블루 스타일과 390x844px 모바일 규격은 유지한다. 각 프롬프트는 2,000자 이하다.

## 1. 기획 충돌 및 내비게이션 수정

```text
현재 TripUS 디자인의 시각 스타일은 유지하면서 기획과 충돌하는 화면을 수정해 주세요.

‘오늘의 여정’에서 실시간 방문 체크 기능을 모두 제거하세요. ‘3곳 중 2곳 방문’, 평가 완료, 방문함·미평가, 아직 방문 전, 방문 표시, 평가 남기기 UI를 사용하지 마세요. 여행 중 화면에는 오늘의 장소 순서, 예상 대중교통 이동시간, 일정 편집, 현장에서 장소 추가, 사용자가 요청하는 동선 재계산, Google Maps 길 찾기만 제공합니다. 방문 상태와 평가는 여행 종료 후 기록 정리에서만 입력합니다.

AI 일정 입력의 ‘여행의 속도: 여유롭게/알차게’는 삭제하세요. 여행 스타일은 관광·맛집·쇼핑 골고루, 맛집·카페·야시장 중심, 유명 관광지 최대한 많이, 여유로운 일정·휴식 중심 네 가지 중 하나만 선택합니다.

전역 하단 메뉴는 ‘내 여행 / 다녀온 여행 / 프로필’로 정리하세요. 여행 내부에는 ‘장소 / 일정 / 지도 / 기록’ 탭을 유지합니다. ‘오늘 일정’은 해당 여행의 일정 탭에서 진입하고, 장소 보관함은 여행의 장소 탭 안에 둡니다. 전역 메뉴와 여행 내부 탭의 역할이 중복되지 않게 해 주세요.

지도 경로는 대중교통 기준임을 명확하게 표현하세요. 구간마다 지하철·버스·도보 아이콘과 예상 시간을 보여주고, 정상 경로는 대중교통 경로선으로 표시합니다. 경로를 찾지 못했을 때만 단순 연결선을 사용합니다. 실제 길 찾기는 ‘Google Maps에서 길 찾기’ 버튼으로 외부 연결합니다. 여행 다시보기에는 ‘방문 순서를 기반으로 재구성한 여정이며 실제 GPS 경로와 다를 수 있습니다’ 문구를 유지하세요.
```

## 2. 장소 저장 및 추천 흐름 추가

```text
현재 TripUS 디자인에 장소 저장과 추천의 전체 흐름을 추가해 주세요. 기존 390x844px 모바일 스타일을 유지합니다.

장소를 저장하는 진입 방식은 앱 검색, 지도에서 선택, Google Maps 링크 붙여넣기, 모바일 공유 메뉴에서 TripUS로 저장하기입니다. 입력 방식 선택 화면과 각 입력 상태를 디자인하세요. 같은 Google Place ID가 이미 저장돼 있으면 중복 저장하지 않고 ‘이미 저장한 장소예요’ 안내와 기존 장소 보기 버튼을 보여주세요.

장소 저장 전 태그를 선택합니다: 관광, 맛집, 카페, 쇼핑, 숙소, 교통, 체험, 기타. 방문 전 선호도는 ‘꼭 가고 싶음 / 가고 싶음 / 시간 되면 방문’ 중 하나를 선택합니다. 저장 완료 후에도 태그와 선호도를 수정할 수 있게 하세요.

장소 상세 화면에는 대표 사진, 장소명, 주소, Google 평점과 평가 수, 운영시간, 지도, 저장 상태, 일정에 추가하기를 배치하세요. ‘운영시간과 휴무일은 변경될 수 있으니 방문 전 최신 정보를 확인해 주세요’ 문구를 포함합니다.

장소 상세 하단에 두 추천 영역을 만드세요. ‘비슷한 장소’는 현재 장소를 대체할 후보이고, ‘함께 가기 좋은 장소’는 현재 일정에 추가하기 좋은 후보입니다. 추천 카드에는 사진, 장소 유형, Google 평점, 추천 이유를 표시합니다. 추천 장소를 선택하면 가장 적합한 날짜와 삽입 위치를 제안하고 적용 전 ‘2일 차에 추가 · 총 이동시간 +18분’처럼 최종 이동시간 증감만 강조합니다. 적용, 취소 버튼과 AI 추천으로 추가된 장소 배지를 포함하세요.
```

## 3. 권한·무료 제한·오류 상태 추가

```text
현재 TripUS 디자인에 빠진 권한, 무료 제한과 예외 상태 화면을 추가해 주세요. 기존 모바일 디자인 시스템을 유지합니다.

여행 소유자는 초대 링크 또는 사용자 초대를 만들 수 있습니다. 초대받은 사용자는 읽기만 가능하므로 ‘읽기 전용’ 배지를 표시하고 장소 추가, 일정 편집, AI 생성, 사진·후기 작성, 삭제 버튼을 비활성화하세요. 읽기 전용 사용자도 일정, 지도, 기록을 보고 Google Maps 길 찾기를 실행할 수 있습니다.

무료 사용자는 활성·보관 여행을 합쳐 1개, 계정 전체에서 AI 생성 1회를 사용할 수 있습니다. 다음 화면을 추가하세요: 무료 AI 1회 실행 전 확인, AI 1회 사용 후 재생성 시 Plus 안내, 보관 여행이 있는 상태에서 새 여행을 만들 때 기존 여행 삭제 또는 Plus 선택, 사진 원본 저장 용량 한도 도달. 자신의 원본 사진 다운로드와 삭제는 결제로 막지 마세요.

공통 예외 상태도 추가하세요: 오프라인 일정 열람, 일반 네트워크 오류, Google 지도 로딩 실패, 장소 검색 결과 없음, 대중교통 경로 없음, 폐업·이전 장소, AI 생성 실패와 횟수 미차감 안내, 사진 업로드 실패와 개별 재시도, 작성 중 후기의 기기 임시 저장.

여행 삭제 확인에는 삭제할 여행명, 복구 불가, 사진과 후기 동시 삭제를 명확히 표시하고 위험 버튼과 취소 버튼을 시각적으로 구분하세요. 진행 중 여행은 비공개이며 외부 공유 링크와 SNS 공유 UI는 만들지 않습니다. ‘최종 일정 9회’ 문구는 ‘방문 기록 9개’로 수정하고, 미래 여행은 ‘여행 예정’, 여행 기간 중에는 ‘여행 중’, 보관 후에는 ‘여행 완료’로 구분하세요.
```

## 4. 디자인 시스템과 프로토타입 정리

```text
TripUS Figma 파일을 개발 전달이 가능한 구조로 정리해 주세요. 현재 모바일 화면의 따뜻한 베이지·코랄·딥블루 스타일은 유지하고, 접근성을 높여 주세요.

페이지를 00 Cover, 01 Foundations, 02 Core Planning, 03 AI Planning, 04 Trip Record, 05 Errors & Limits, 06 Components, 07 Prototype로 분리하세요. Foundations에는 색상, 한국어 타이포그래피, 간격, 모서리, 그림자, 아이콘과 390px 모바일 그리드를 정의하세요. 본문과 보조 문구가 너무 작거나 대비가 낮지 않게 WCAG AA 수준의 대비와 터치 영역 최소 44px을 적용하세요.

Components에는 버튼, 입력창, 하단 메뉴, 여행 내부 탭, 여행 카드, 장소 카드, 추천 카드, Google 평점, 태그 칩, 방문 전 선호도, 방문 후 만족도, 날짜 헤더, 일정 항목, 순서 마커, 교통수단과 이동시간, 잠금, AI 추천 배지, 미배치 이유, 인라인 경고, 오프라인 배너, 사진 업로드, 토스트, Plus 안내, 삭제 모달을 컴포넌트와 상태 variant로 만드세요.

클릭 가능한 프로토타입을 연결하세요. 흐름 1: 여행 생성→장소 저장→숙소 설정→AI 스타일 선택→무료 1회 확인→AI 결과→일정 편집→Google Maps 길 찾기. 흐름 2: 일정 잠금→이 날짜만 다시 짜기→변경 비교→적용→한 번 되돌리기. 흐름 3: 여행 종료→평가/미평가/미방문 정리→사진과 후기→보관→지도 다시보기. 흐름 4: 읽기 전용 초대. 흐름 5: 무료 한도 도달→Plus 안내 또는 기존 여행 삭제.
```
