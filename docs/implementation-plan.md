# TripUS 구현 계획

## 목표

첫 릴리스는 Figma의 핵심 사용자 흐름을 실제로 이동하고 조작할 수 있는 모바일 우선 MVP 기반으로 만든다. Google Maps와 AI는 목업이지만 실제 교체 경계를 유지한다.

## 마일스톤

### M0. 기획 동기화와 기반 결정

- 최신 제품 결정 반영
- 기술 아키텍처·폴더 구조 확정
- 기존 소스 제거 상태를 기획 브랜치에 커밋
- `codex/mvp-foundation` 브랜치 생성

완료 조건: 제품 문서와 구현 기준 사이에 알려진 충돌이 없다.

### M1. 프로젝트 기반과 디자인 시스템

- Next.js, TypeScript, ESLint, Drizzle 기본 구성
- 모바일 앱 셸, 색상·타이포·간격 토큰
- 버튼, 입력, 카드, 칩, 하단 내비게이션
- PWA manifest와 기본 아이콘
- 목업 저장소, 지도·AI 어댑터 인터페이스

완료 조건: 외부 키 없이 설치·타입 검사·빌드가 성공하고 모든 핵심 라우트가 열린다.

### M2. 계획 핵심 흐름

- 로그인
- 내 여행과 여행 생성
- 모든 저장 장소의 장소 보관함
- 장소 검색·저장 목업
- 여행 스타일 선택으로 시작하는 AI 일정
- 날짜별 일정 편집과 미배치 관리
- 일정 충돌·대중교통 경로 실패 예외 화면

완료 조건: 로그인부터 일정 편집까지 한 방향으로 끊김 없이 진행되고 새로고침 후 데모 상태가 유지된다.

### M3. 여행 완료와 기록

- 상태 탭 없는 완료 정리
- 방문 장소 별점 1~5점
- 별도 미방문 지정과 되돌리기
- 별점 없는 완료/정리 없는 보관의 미평가 처리
- 방문별 후기·사진 인라인 추가 UI
- 완료 여행 요약

완료 조건: 일정의 모든 방문이 rated, unrated, not_visited 중 하나로 일관되게 전환된다.

### M4. 영속화와 실연동 준비

- PostgreSQL/Drizzle 저장소 연결
- 인증 도입
- Google Places/Routes 어댑터 구현과 정책 검증
- AI 공급자 어댑터 구현, 비용·횟수 처리
- 사진 저장·최적화·EXIF 제거 파이프라인

완료 조건: 목업 어댑터를 환경 설정으로 실제 어댑터와 교체할 수 있다.

### M5. 품질과 배포

- 핵심 흐름 E2E
- 접근성·반응형·오프라인 최소 열람 점검
- 오류 관측과 제품 이벤트
- 배포 환경, 개인정보·삭제 정책 검증

완료 조건: 배포 후보가 핵심 시나리오와 비기능 기준을 통과한다.

## 첫 구현 범위

이번 개발 브랜치에서는 M1부터 M3까지의 연결된 목업 경험을 우선한다. 인증·PostgreSQL·실제 지도·실제 AI·실제 사진 업로드는 구조와 스키마까지만 준비하고 런타임은 목업으로 유지한다.

## 기술 선택 유예

- 인증 공급자: 배포 환경과 소셜 로그인 범위가 정해진 뒤 결정
- 객체 저장소/CDN: 원본 무제한 정책의 실제 사용량과 삭제 SLA를 측정한 뒤 결정
- AI 모델/공급자: 일정 품질 평가셋과 호출 비용을 만든 뒤 결정
- 지도 세부 API: 국가별 대중교통 지원과 Google 정책을 최신 공식 문서로 검증한 뒤 결정

이 선택들은 현재 핵심 UI 흐름 구현을 막지 않도록 포트와 목업 어댑터 뒤에 둔다.
