# 모바일 공유 캐시

2026-11-17부터 TanStack Query v5를 사용한다. `shared/query/query-client.ts`의 QueryClient를 루트 Provider와 도메인 조회 API가 공유한다. 쿼리 키는 `account / userId / resource`로 구성한다. 같은 자원은 `defineQuery`의 요청 함수와 options를 훅·명령형 호출이 공유한다. 라이브러리·숙소·일정의 장소 조회도 하나로 합친다.

| 데이터 | 최신으로 보는 시간 | 공유 범위 |
| --- | --- | --- |
| 진행 중 여행 목록 | 1분 | 홈·공유 장소 저장 |
| 지난 여행 목록 | 5분 | 홈의 지난 여행·지난 여행 탭 |
| 여행 상세 | 1분 | 여행·편집 초기값·AI 입력·일정·기록·캐러셀 |
| 저장 장소 | 1분 | 보관함·기본 숙소·일정·장소 선택기 |
| 일정 | 1분 | 상세 개수·일정 편집·AI 이전 상태·기록·캐러셀 |
| 기록 사진 | 1분 | 완료 편집·기록·캐러셀 |
| 플랜·한도 | 1분 | 프로필·업그레이드·여행 생성·AI 입력 |
| 마지막 AI 입력 | 5분 | AI 입력 복원 |
| 여행 표지·장소 사진 URL | 5분 | 목록·상세·장소 카드, 메모리만 |
| 장소 검색 | 1분 | 여행/목적지·검색어·지도 범위별 |
| 도시 검색 | 24시간 | 국가·국가 코드·검색어별 |
| 이동 구간 | 성공 5분, 조회 불가 15초 | 여행·방향·날짜·출발 시각·양쪽 위치별 |
| AI 실행 상태 | 1초 | 실행 중 2초 간격 조회의 중복 호출 방지 |

비활성 자원의 메모리 보관은 기본 30분, 구간은 5분이다. 최신으로 보는 시간은 메모리 보관 기간을 늘리지 않는다. 화면 focus는 `fetchQuery`로 최신 여부를 확인하며 앱 활성화·네트워크 복구는 Query manager에 연결한다. 다시 시도 버튼은 `refetch`로 강제 갱신한다. 조회와 변경 요청을 자동 재시도하지 않는다. AI 상태의 일시적인 조회 실패는 기존 작업 대기를 유지한다.

| 변경 | 즉시 반영 | 추가 조회가 필요한 파생 데이터 |
| --- | --- | --- |
| 여행 생성 | 여행 상세·이미 로드한 진행 중 목록 | 플랜 사용량 |
| 여행 수정 | 여행 상세·진행 중/지난 여행 목록 | 일정 경계, 첫 지역이 바뀐 경우 표지 |
| 여행 삭제 | 양쪽 목록 제거·여행 하위 캐시 제거 | 플랜 사용량 |
| 장소 저장·수정·삭제 | 로드한 장소 목록 | 일정 미배치·경계·삭제 연관 항목, 변경 장소 사진/구간 |
| 일정 저장·되돌리기 | PUT 응답 일정 | 없음 |
| AI 생성 완료 | 새 일정·마지막 전체 생성 입력 | 새 장소·플랜 사용량 |
| 여행 보관·기록 수정 | 완료 응답의 여행·일정, archivedAt 기준 양쪽 목록 | 없음 |
| 사진 업로드 확인 | 로드한 사진 목록에 확정 응답 반영 | 없음 |
| 플랜 업그레이드 | 응답 플랜·한도 | 없음 |

아직 조회하지 않은 목록에 단일 변경 응답만 넣어 완전한 목록처럼 만들지 않는다. 저장 응답을 반영하기 전 진행 중인 같은 자원의 조회를 취소하고, 늦게 도착한 읽기 결과가 최신 저장값을 덮어쓰지 않게 한다. 계정이 바뀐 동안 끝난 변경·AI 작업은 새 계정 캐시에 반영하지 않는다.

SQLite는 여행 목록·상세·장소·일정 및 AI 되돌리기 스냅샷을 계정별로 보관한다. 시작 시 원래 저장 시각으로 복원하므로 오래된 데이터가 새 데이터로 취급되지 않는다. AI 되돌리기는 일반 조회 캐시로 복원하지 않는다. 계정 구분이 없는 예전 데이터는 재사용하지 않는다. 짧은 수명의 사진 URL, 검색 결과, 경로 응답, 토큰·세션, 업로드 대상/바이트, 텔레메트리는 Query 영속 대상에서 제외한다. 표지·장소 사진 픽셀은 디스크 대신 이미지 메모리 캐시를 사용한다.

일정 편집의 서버 스냅샷과 로컬 초안은 분리한다. 초안에 변경이 있거나 저장/AI 처리 중이면 백그라운드 갱신으로 초안을 바꾸지 않는다. DnD는 구간 키를 변경하고 새 요청/재조회 중 이전 소요 시간 대신 스피너를 표시한다. AI 요청에 이동 시간을 다시 요구하지 않는다.

탐색은 탭 → 전체 화면 여행 작업 공간 → 편집/미리보기 구조다. 작업 공간·편집·미리보기는 오른쪽에서 들어오고 닫을 때 오른쪽으로 나간다. 네이티브 스택의 card + slide_from_right 전환을 사용하며 작업 공간만 닫아 실제 진입 탭과 목록 스크롤을 유지한다. 기존 URL은 유지한다. 미저장 변경 확인은 Expo Router의 usePreventRemove로 뒤로가기와 부모 작업 공간 닫기까지 보호한다. 전체 화면 위의 팝업은 화면별 호스트에서 표시한다.

회귀 테스트는 공유 요청 수, 최신 캐시 재사용, 백그라운드 갱신과 실패, 완료 응답 반영, 계정 격리, 영속 시각, 늦은 응답, 일정 초안과 구간 스피너를 검증한다. iOS 실제 전환은 시뮬레이터에서 확인하며 Android 네이티브 전환은 별도 기기 검증 대상이다.
