# UI·제품 기획 변경 기록

사용자가 실제로 보는 화면과 서비스 동작의 변경 이유를 추적하는 문서다. 최신 변경을 위에 추가한다.

## 기록 기준

- **UI 변경:** 화면 구조, 컴포넌트, 문구, 상태 표시, 입력 방식, 탐색 흐름
- **기획 변경:** 사용자 정책, 기능 범위, 생성·검증 규칙, 예외 및 실패 처리
- **기록 제외:** 사용자 경험에 영향을 주지 않는 내부 리팩터링, 테스트 코드만의 변경

각 항목에는 대상, 변경 내용, 이유, 사용자 영향과 관련 커밋을 기록한다. 기존 제품 기준 자체가 달라지면 `product-plan.md` 등 관련 기준 문서도 함께 수정한다.

## 2026-11-14

### 여행 캐러셀 콘텐츠 자동 분할과 영역 보호

- **대상:** 여행 캐러셀의 전체 동선·날짜별 기록·베스트 화면
- **유형:** UI 및 제품 동작 변경
- **변경 내용:** 고정된 4:5 이미지 한 장에 모든 내용을 밀어 넣던 방식을 제거했다. 전체 동선은 최대 3일씩, 날짜별 방문 기록은 최대 3곳씩 자동으로 다음 장에 이어지며 분할된 장에는 현재 순서를 표시한다. 긴 여행 제목·장소명·후기는 각 영역 안에서 줄 수를 제한하고, 사진과 베스트 영역의 높이 및 축소 규칙을 명시했다.
- **이유:** 여행 일수, 하루 방문 장소 수와 후기 길이에 따라 카드가 다른 영역을 침범하거나 이미지 경계에서 잘리는 문제를 방지하기 위해서다.
- **사용자 영향:** 일정과 기록이 많아도 내용이 별도 이미지로 자연스럽게 이어지며, 각 캐러셀 이미지의 구성 요소가 겹치거나 잘리지 않는다.
- **관련 커밋:** 이 변경을 포함한 커밋

### 여행 캐러셀 전체 날짜 구성과 완료 기록 수정

- **대상:** 여행 캐러셀, 여행 기록 상세, 여행 완료 정리
- **유형:** UI 및 제품 기획 변경
- **변경 내용:** 캐러셀은 일정 항목이 있는 날짜만 추리던 방식에서 여행 시작일부터 종료일까지 모든 날짜를 하루당 한 장씩 만드는 방식으로 변경했다. 사진이 없는 표지와 날짜 화면은 단순 선 장식 대신 여행 일수·장소 수와 날짜별 장소를 담은 기록 카드로 표현한다. 완료한 여행 기록에서도 기존 사진·별점·후기를 불러와 추가·수정할 수 있으며, 저장할 때 변경하지 않은 기록도 유지한다. 여행 기록 상단의 `지난 여행` 고정 문구는 해당 여행 제목으로 변경했다.
- **이유:** 장기 여행의 일부 날짜가 캐러셀에서 누락되고, 사진이 없는 화면의 표현력이 낮으며, 완료 이후 기록을 보완할 수 없었던 문제를 해결하기 위해서다.
- **사용자 영향:** 여행 기간 전체가 캐러셀에 빠짐없이 남고 사진이 적어도 완성도 있는 결과를 확인할 수 있으며, 보관 후에도 여행의 사진과 평가를 계속 보완할 수 있다.
- **관련 커밋:** 이 변경을 포함한 커밋

### Figma 디자인 시스템과 화면 상태 기준 정리

- **대상:** TripUS Figma 파일의 Foundations, Components, Screens
- **유형:** UI 설계 기준 변경
- **변경 내용:** 모바일 코드의 색상·간격·모서리·타이포그래피 토큰을 Figma 로컬 변수와 텍스트 스타일로 동기화했다. 버튼, 필터 Pill, 장소 카드, 일정 카드에 실제 서비스 상태를 반영한 재사용 컴포넌트와 변형을 추가했다. 화면 이름에는 `CURRENT`, `REVIEW`, `REFERENCE` 상태를 구분해 표시하고 상태별 사용 기준을 설명하는 Source of Truth 가이드를 추가했다. AI 일정 만들기와 일정 편집 화면은 세로 스크롤이 가능하도록 프로토타입 설정을 보완했다.
- **이유:** 구현 코드와 디자인 파일의 색상·컴포넌트 기준이 달랐고, 현재 화면·개선안·참고 화면이 한 페이지에 섞여 작업 기준을 판단하기 어려웠기 때문이다.
- **사용자 영향:** 이후 UI 변경 시 실제 앱과 같은 토큰과 컴포넌트를 재사용할 수 있어 화면 간 일관성이 높아지고, 검토 중인 안이 현재 서비스 화면으로 오인될 가능성이 줄어든다.
- **관련 커밋:** 이 변경을 포함한 커밋

### AI 일정 검증 재작성 강화

- **대상:** AI 일정 생성 및 날짜별 일정 업데이트
- **유형:** 제품 기획 변경
- **변경 내용:** 서버 검증에서 일정 누락·시간 부족·시간 범위 위반 등이 발견되면 검증 사유뿐 아니라 탈락한 직전 전체 응답도 AI에 다시 전달한다. AI는 정상인 방문을 유지하면서 지적된 항목을 모두 보완한 전체 일정을 다시 작성한다. 검증 후에도 하루 일정이 선택한 밀도의 목표 시간에 미달하면 더 이상 성공 결과로 통과시키지 않으며, 검증·재작성은 최대 3회 수행한다. 식사 누락처럼 서버가 별도 보정하는 항목은 기존처럼 서버에서 보완한다.
- **이유:** 직전 응답을 보지 못한 AI가 같은 누락을 반복하고, 짧은 일정이 내부 재요청 후에도 성공으로 저장되던 문제를 해결하기 위해서다.
- **사용자 영향:** 검증 단계에서 발견 가능한 일정 품질 문제는 사용자에게 실패를 반환하기 전에 직전 초안을 기준으로 구체적으로 수정되며, 끝까지 기준을 충족하지 못한 실제 실패만 실패로 안내된다.
- **관련 커밋:** 이 변경을 포함한 커밋

### 여행 완료 정리와 기록 화면 안정화

- **대상:** 여행 완료 정리, 여행 기록, 프로필, 공통 입력 UI
- **유형:** UI 및 제품 동작 변경
- **변경 내용:**
  - 모든 검색·입력 placeholder 색상을 명시해 실기기 테마에 관계없이 보이도록 변경했다.
  - 미방문 칩이 카드 내부에 유지되도록 배치를 조정했다.
  - 미방문 장소에서는 별점, 메모, 사진 추가 기능을 제공하지 않는다.
  - 여행 기록 화면의 뒤로가기는 완료된 여행 상세가 아니라 `지난 여행` 목록으로 이동한다.
  - 플랜 정보를 불러오기 전에는 `Free 플랜` 대신 `플랜 확인 중…`을 표시한다.
  - 사진 저장소 장애는 여행 보관과 기록 조회를 막지 않으며 사진 기능에 한정해 안내한다.
- **이유:** 실기기 가독성 문제와 완료된 여행이 다시 편집 가능한 화면으로 연결되는 혼란을 제거하고, 선택한 방문 상태와 입력 가능한 기록을 일치시키기 위해서다.
- **사용자 영향:** 여행 완료·보관 흐름이 중간 서비스 장애에도 유지되고, 완료 후 탐색 경로가 명확해진다.
- **관련 커밋:** `6642f07`

### AI 일정 최종 검증 완화와 시간표 보정

- **대상:** AI 일정 생성 서버 검증
- **유형:** 제품 기획 변경
- **변경 내용:** 생성된 방문 시간이 해당 날짜의 사용 가능 시간을 넘으면 서버가 방문 시간을 압축하고 순차 재배치한다. 일정 밀도가 목표보다 조금 낮은 경우에는 사용 가능한 결과 전체를 폐기하지 않는다. 저장 장소 누락이나 잘못된 시간표처럼 실제 사용을 방해하는 문제는 계속 차단한다.
- **이유:** 충분히 사용할 수 있는 일정이 엄격한 밀도 조건 하나 때문에 전체 실패로 노출되는 문제를 방지하기 위해서다.
- **사용자 영향:** AI 응답이 완벽하지 않더라도 서버가 안전하게 보정 가능한 경우 일정 생성 결과를 받을 수 있다.
- **관련 커밋:** `6642f07`
