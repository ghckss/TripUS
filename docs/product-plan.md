# TripUS 서비스 기획서

## 1. 문서 목적

TripUS는 여행 전에 가고 싶은 장소를 모아 날짜별 방문 흐름을 계획하고, 여행 후에는 사진과 후기를 더해 하나의 여행 기록으로 남기는 서비스다.

이 문서는 현재까지 확정된 제품 원칙, 핵심 사용자 흐름, 기능 범위, 데이터 개념, 운영 정책과 MVP 우선순위를 정의한다.

### 모바일 디자인 기준

2026-11-15부터 모바일 UI는 Figma의 **여행의 여백 · Field Notes**를 사용한다. 크림색 배경과 벽돌색 강조, 세리프 제목, 얇은 구분선, 수첩 형태의 여행 카드로 통일한다. 색상·서체·간격·컴포넌트·에셋과 정적 시안의 실제 제품 적용 원칙은 [Field Notes 디자인 시스템](./design/field-notes.md)을 따른다. 여행 내부에는 여행·장소·일정·기록 탐색을 제공하고, 장소 보관함은 저장된 장소 이름·메모 검색과 분류·선택 관리를 지원한다. 정적 디자인의 예시 데이터로 실제 지도나 API 데이터를 대체하지 않으며 기존 생성·검증·명시적 저장 정책을 유지한다.

## 2. 제품 한 문장

> 가고 싶은 곳을 저장하면 AI가 날짜별 방문 흐름을 구성하고, 여행이 끝난 뒤 그 일정을 사진과 후기가 담긴 여행 기록으로 완성해 주는 앱.

## 3. 해결하려는 문제

여행자는 가고 싶은 장소를 여러 곳에서 발견하지만, 이를 날짜별로 묶고 효율적인 방문 순서를 만드는 데 많은 시간을 쓴다. 여행 후에는 사진이 기기에 흩어지고 장소별 기억을 체계적으로 남기기 어렵다.

TripUS는 다음 두 문제를 연결해서 해결한다.

1. 여행 전: 저장한 장소를 날짜별로 묶고 방문 흐름을 만드는 수고를 줄인다.
2. 여행 후: 계획에 사진, 점수와 후기를 더해 다시 볼 수 있는 여행 기록으로 만든다.

## 4. 제품의 역할과 한계

TripUS는 분 단위의 완벽한 일정표나 실시간 내비게이션을 제공하는 앱이 아니다. 사용자가 방문하려는 장소를 날짜별로 묶고, 순서와 전체 흐름을 이해하도록 돕는 여행 관리 앱이다.

### TripUS가 제공하는 것

- 가고 싶은 장소 저장 및 분류
- AI 기반 날짜별 장소 분배와 방문 순서 제안
- 숙소를 매일 첫·마지막 방문 일정으로 포함한 동선
- 실제 좌표와 방문 순서를 기반으로 한 지도 동선
- 비슷한 장소와 함께 가기 좋은 장소 추천
- 사용자가 자유롭게 수정할 수 있는 일정
- 여행 후 사진, 점수와 후기 기록
- 날짜별 지도 재생과 여행 다시보기

### TripUS가 제공하지 않는 것

- 앱 내부 턴바이턴 내비게이션
- 실시간 위치 추적 또는 자동 방문 판정
- 여행 중 방문 완료 체크
- 장소별 체류 시간 계산
- 실제 도착시간 또는 운영시간 보장
- 항공, 기차, 공연, 예약을 위한 별도 캘린더 기능
- 교통 지연을 감지한 자동 일정 변경

## 5. 핵심 타깃

### 대상

- 국내 또는 해외 자유여행자
- 대중교통 중심 여행자
- 여행 전 여러 장소를 저장하고 촘촘하게 계획하는 사용자
- 초행지 또는 재방문 여행자
- 혼자 또는 동행자와 여행하는 사용자

혼자 여행인지 동행 여행인지는 초기 AI 최적화 조건으로 사용하지 않는다. 즉흥 여행자는 생성된 일정에서 필요 없는 장소를 직접 제거해 사용할 수 있다.

### 재방문 여행

재방문 여행에는 다음 정보를 보여준다.

- 해당 도시 또는 지역의 과거 방문 횟수
- 마지막 방문일
- 이전에 방문한 장소
- 이번에도 다시 방문하는 장소
- 이번에 처음 방문하는 장소

사용자 행동을 학습한 고도화 추천은 To-Be로 두며, MVP에서는 방문 이력 정보 제공에 집중한다.

## 6. 핵심 제품 원칙

1. 사용자는 먼저 장소를 저장하고, 날짜별 배치는 AI가 돕는다.
2. AI 결과는 확정안이 아니라 사용자가 수정할 수 있는 초안이다.
3. AI는 모든 장소를 억지로 일정에 넣지 않는다.
4. 기본 숙소를 제외한 저장 장소는 장소 보관함의 단순 목록에 유지하고, 일정 포함 여부는 일정 편집에서 관리한다.
5. 같은 장소를 여러 날짜에 반복 배치할 수 있으며 계획 단계에서는 각 방문을 독립적인 일정 항목으로 관리한다. 여행 완료 정리에서는 같은 저장 장소를 한 번만 보여준다.
6. 사용자의 수동 편집을 AI가 임의로 다시 변경하지 않는다.
7. 운영시간, 이동시간과 경로는 참고 정보이며 정확성을 보장하지 않는다.
8. 여행 완료 후 계획과 기록을 두 벌로 보관하지 않고 하나의 최종 여행 데이터로 관리한다.
9. 일정 편집 지도는 방문 흐름을 확인하는 용도이며 수동 대중교통 조회나 외부 길 찾기 버튼을 제공하지 않는다.
10. 진행 중인 여행은 외부에 공개하지 않는다.

## 7. 여행 생명주기

### 7.1 여행 생성

사용자는 여행명, 여행지, 여행 기간(시작일~종료일), 선택 사항인 시작·종료 장소와 기본 숙소 정보를 입력한다.

- 생성·수정 화면의 여행 기간은 한 달력에서 시작일과 종료일을 선택하고 `기간 적용`으로 확정한다. 월을 넘는 범위와 시작일·종료일이 같은 당일 여행을 지원한다. 취소 시 기존 기간을 유지한다.
- 종료일 선택 중 시작일보다 앞선 날짜를 고르면 시작일을 해당 날짜로 바꾸고 종료일을 다시 선택한다.
- 시작·종료 장소가 모두 비었을 때만 첫 선택 장소를 반대쪽에도 자동 입력한다. 어느 한쪽이라도 이미 입력됐으면 반대쪽을 변경하지 않는다. 기존 여행 조회에는 이 자동 입력을 적용하지 않는다.
- 자동 입력은 장소 정보만 복사하며 시작·종료 지점의 선택적 시각은 각각 유지한다. 국가 변경으로 두 장소를 초기화하면 다음 첫 선택 시 자동 입력 조건을 다시 적용한다.

- 실제 날짜가 정해지지 않았더라도 임시 날짜를 반드시 입력한다.
- 화면에는 정확한 날짜와 요일을 표시한다.
- 날짜가 변경되면 운영시간과 대중교통 경로를 다시 확인한다.
- 여행에는 여행지 기준 IANA 시간대를 저장한다.
- 일정의 날짜와 시간은 기기 시간대가 아니라 여행지 현지 시간으로 표시한다.
- 기본 숙소는 여행 생성 후에도 여행 정보 수정에서 변경하거나 제거할 수 있다.

### 7.2 계획 중

오늘과 미래 날짜의 일정은 계획 중으로 취급한다.

- 장소 저장
- 숙소 등록
- 날짜별 시작·종료 시간 설정
- AI 일정 생성
- 직접 추가·삭제·순서 변경

### 7.3 지난 날짜

오늘보다 이전 날짜는 완료된 날짜로 취급한다. 다만 실시간 방문 체크는 하지 않으며, 장소의 최종 방문 상태는 여행 기록 정리 과정에서 결정한다.

### 7.4 여행 종료 및 보관

사용자는 여행을 직접 보관할 수 있다.

- 여행 정리는 상태 탭을 먼저 고르는 방식이 아니다. 방문한 장소에는 필요할 때 별점 1~5점을 입력하고, 방문하지 않은 장소만 `미방문` 버튼으로 별도 지정한다.
- 방문한 장소에 별점을 입력하면 `평가 완료`, 별점 없이 정리를 완료하면 `미평가`가 된다.
- 계획에 없던 추가 방문 장소를 등록할 수 있다.
- 정리 없이 보관하면 일정에 배치된 장소를 모두 방문한 것으로 보고 `미평가`로 처리한다.
- 일정에 포함되지 않은 저장 장소는 방문 처리하지 않는다.
- 미평가 장소는 만족도, 추천 학습 등 점수 기반 통계에서 제외한다.
- 보관된 여행은 `다녀온 여행` 목록에서 열람한다.

## 8. 여행과 날짜 설정

### 날짜별 시간

각 날짜에는 사용자가 시작 시간과 종료 시간을 설정할 수 있다.

- 기본 시작 시간: 09:00
- 기본 종료 시간: 24:00
- 사용자가 종료 시간보다 늦은 장소를 입력해도 저장을 차단하지 않는다.
- 충돌은 경고만 표시한다.
- UI의 24:00은 내부적으로 다음 날짜 00:00과 혼동되지 않게 처리한다.

날짜별 시간은 AI가 하루의 이용 가능한 시간을 판단하기 위한 참고값이다. 장소별 체류 시간을 제공하지 않으므로 분 단위의 정확한 종료 시각은 계산하지 않는다.

### 숙소

숙소는 일반 장소 태그이면서 하루 일정의 시작과 끝에 배치되는 특별한 방문 일정이다.

- 사용자는 여행 정보 설정에서 기본 숙소를 등록한다.
- 기본 숙소는 별도 설정 화면 없이 각 날짜 방문 일정의 첫 항목과 마지막 항목으로 자동 추가한다.
- 기본 숙소는 여행 장소 보관함과 일정 배치 후보에는 노출하지 않는다.
- 날짜별 활동 시작·종료 시간은 일정 편집에서 변경한다.
- 별도의 `출발 숙소`, `종료 숙소` 필드나 선택 UI는 제공하지 않는다.
- 숙소가 없으면 숙소 항목 없이 일정을 생성한다.
- 야간열차 등 특수한 숙박은 일반 장소 또는 메모로 처리한다.

## 9. 장소 저장 및 관리

### 저장 진입 경로

- 앱 내부 장소 검색
- 일정 편집의 `여행 장소 추가`에서 미등록 장소 검색·저장·즉시 선택
- 지도에서 장소 선택
- Google Maps 링크 붙여넣기
- 모바일 공유 메뉴에서 TripUS로 저장
- 동일한 Google Place ID의 중복 장소 병합

외부 Google Maps 저장 목록 전체 가져오기는 API와 정책 검증 전까지 제공하지 않는다.

### 장소 추가 화면의 지도 검색과 설명

- Google 지도를 표시하고 여행 지역 또는 시작·종료 장소의 실제 좌표로 초기 위치를 잡는다. 좌표가 없으면 전체 지도와 여행지 기반 검색을 제공한다.
- 검색 버튼과 `이 지역에서 검색`은 검색어와 현재 지도 화면의 경계를 함께 사용한다. 지도 이동만으로 자동 검색하지 않는다. Google Places Text Search 결과 중 영역 안의 장소를 최대 10개 표시하며 지도 핀과 결과 선택을 연결한다.
- 선택한 장소에 `설명 추가 (선택)`을 입력할 수 있다. 설명은 앞뒤 공백을 제거해 기존 장소의 note 필드에 저장하며 빈 입력은 생략한다. 장소를 바꿔 선택하거나 저장에 실패해도 작성한 설명은 유지한다.
- 이미 저장한 장소는 중복으로 만들지 않으며 새로 입력한 설명으로 기존 설명을 덮어쓰지 않는다.

### 장소 태그

사용자는 장소에 최소한의 태그를 선택한다.

- 관광
- 맛집
- 카페
- 쇼핑
- 숙소
- 교통
- 체험
- 기타

### 장소 보관함 표시

- 장소 카드는 왼쪽에 세로로 충분한 크기의 대표 이미지를, 오른쪽에 한 줄 장소명과 최대 세 줄의 실제 장소 설명을 표시한다. 설명 데이터가 없거나 일정 제외·공간 부족·보관함 저장 같은 내부 사유뿐이면 설명 영역을 비워 둔다. 체크박스는 두지 않으며 카드를 누르면 배경색과 테두리색이 바뀌어 선택 상태를 나타낸다. 장소 태그는 카드에 반복 노출하지 않고 상단 필터에서만 사용한다.
- AI 일정 생성 시 저장 장소의 설명이 비어 있으면 장소 자체의 특징과 방문 가치에 대한 설명을 함께 생성해 저장한다. 사용자가 작성했거나 기존에 저장된 설명은 덮어쓰지 않는다.
- 이미지 아래의 출처·저작자 텍스트, 주소, `Google Maps에서 사진 보기`, `점심 일정 보완` 같은 내부 출처·보정 문구는 카드 본문으로 노출하지 않는다.
- `장소 추가`는 목록 상단 콘텐츠가 아니라 화면 하단의 고정 동작으로 제공해 스크롤 위치와 관계없이 접근할 수 있게 한다.

### 방문 전 선호도

- 꼭 가고 싶음
- 가고 싶음
- 시간이 되면 방문

방문 전 선호도와 방문 후 만족도는 별도 값으로 관리한다. 만족도 수정이 방문 전 선호도를 덮어쓰지 않는다.

### 장소 보관함과 일정 항목

저장 장소와 날짜별 일정 항목은 분리한다.

- 장소 보관함은 기본 숙소를 제외하고 사용자가 저장한 여행 장소를 보여주는 단순 목록이다.
- 보관함 자체에는 미배치 전용 탭이나 일정 포함 여부 필터를 두지 않는다.
- 저장 장소는 원본 후보로 유지한다.
- 일정에 넣어도 저장 장소에서 제거하지 않는다.
- 동일 장소를 여러 일정 항목으로 만들 수 있다.
- 일정 항목을 제거해도 저장 장소는 남는다.
- 일정 포함 여부는 일정 편집의 각 날짜별 장소 선택 화면에서 관리한다.

## 10. 장소 추천

### 추천 유형

2. 함께 가기 좋은 장소: 현재 여행 동선에 자연스럽게 추가할 수 있는 장소

### 추천 판단 요소

- 선택한 장소와의 거리
- 현재 날짜의 방문 흐름
- 대중교통 접근성
- 운영시간
- Google 평점과 평가 수
- 사용자가 저장한 다른 장소
- 방문 전 선호도

### 추천 카드

- 장소명과 대표 이미지
- 장소 유형
- Google 평점과 평가 수

## 11. AI 일정 생성

### 시작

사용자가 `일정 만들기`를 선택하면 첫 화면으로 여행 스타일 선택 화면을 연다. 기본 숙소는 여행 정보에서 입력하고 매일 첫·마지막 방문 일정으로 자동 추가한다. 날짜별 활동 시간은 일정 편집에서 변경한다. 별도의 숙소 및 날짜 설정 화면은 제공하지 않는다.

### 여행 스타일

- 관광·맛집·쇼핑을 골고루
- 맛집·카페·야시장 중심
- 유명 관광지를 최대한 많이
- 여유로운 일정과 휴식 중심

날짜별 시작·종료 시간은 이 질문에서 다시 받지 않고 날짜 설정에 저장된 값을 사용한다.

### 생성 규칙

AI 일정 생성은 영속 비동기 작업으로 실행한다. 앱의 요청에는 즉시 작업 ID를 반환하고, 요청 내용·대상 날짜·사용자·진행 상태는 서버 DB에 저장한다. 앱은 작업 ID의 상태를 조회하면서 로딩 화면을 유지하며 장시간 HTTP 연결 자체를 생성 성공 조건으로 사용하지 않는다. 네트워크가 일시적으로 끊기거나 API가 재시작되어도 저장된 미완료 작업을 이어서 처리하고, 서버가 최종 실패를 확정한 경우에만 사용자에게 실패 안내를 표시한다. 같은 여행에는 AI 생성 작업을 동시에 하나만 실행한다.

AI에는 기본 여행 정보와 선택한 여행 방식을 전달한다.

1. 여행 제목, 목적지와 지역, 시작일·종료일, 몇 박 며칠인지와 현지 시간대
2. 등록된 숙소의 이름·주소·좌표
3. 일정 시작·종료 장소의 이름·주소·좌표·시간
4. 사용자가 등록한 방문 장소의 ID·이름·주소·좌표·분류·선호도·메모
5. 이번에 생성할 날짜 목록(날짜별 업데이트면 해당 날짜)과 날짜별 출발·복귀 숙소
6. preferences.themes(복수 선택한 여행 방식)

생성 범위는 `itineraryDates`로 한정한다. 전체 여행 기간은 참고 정보이며, 날짜별 업데이트에서는 대상 하루만 반환하며 중간 날짜에 여행 첫날의 시작 시각을 적용하지 않는다. 응답의 `days[].date`는 대상 날짜 목록 안에 있어야 하며, 등록 장소의 입력 식별자 `places[].id`를 방문의 `savedPlaceId`에 그대로 사용한다. 새 장소는 같은 방문 배열에서 `savedPlaceId: null`로 구분한다.

기존 복잡한 생성·수정·분야별 검토 흐름과 서버의 관광 수·체류 목표 검증은 사용하지 않는다. 운영시간 확인과 시간표 구성은 아래의 웹 검색·방문 지침으로 다룬다. 동행자·예산·교통수단·추가 요청 입력은 호환성을 위해 저장하지만 현재 모델 입력에는 전달하지 않는다.

밀도 선택 기능을 제공하지 않는다. 여행 생성 화면의 밀도 선택·설명·상태, 요청·응답의 density 필드와 TravelDensity 타입, 모델 입력의 밀도·관광 수 목표를 제거한다. 관광 장소의 목표·최소·최대 개수나 방문 수 배수를 미리 정하지 않고, 실제 가용 시간·장소별 관람 특성·운영시간·동선·사용자가 선택한 여행 방식을 기준으로 방문 구성을 결정한다. 단순히 방문 수나 분량을 채우기 위해 장소를 추가하지 않는다.

여행 방식은 최초 생성과 날짜별 업데이트 모두에 실제 선택값을 전달한다. 날짜별 업데이트는 저장된 최근 설정의 방식을 재사용하고, 최근 설정이 없으면 대표 명소를 기본값으로 사용한다. 과거 요청 JSON에 남아 있는 밀도는 최근 설정 응답·AI 입력·기본값 결정에 사용하지 않으며, 재저장할 때도 복사하지 않는다. 기존 일정 데이터는 그대로 유지한다.

등록 장소가 없어도 날짜별 visits에 실제 장소를 선정해 관광·식사 시간표를 완성한다. 별도 경계 시각이 없는 온전한 관광일은 현지 09:00~21:00를 계획 가능 범위로 참고하되 의무적으로 채우지 않는다. 식사가 가능한 온전한 날은 점심·저녁을 특정 식당의 실제 방문으로 포함하고, mealType을 lunch·dinner로 일치시킨다. 경계 시각 때문에 식사시간이 범위 밖인 부분 날짜는 해당 식사를 조정한다. 업장 미정·권장 지역 표현은 식당 방문으로 반환하지 않는다.

체류시간의 계획 출발점은 사진·외관 15~30분, 소규모 명소 30~60분, 일반 관광·체험 60~90분, 대형 박물관·궁전 120~180분, 일반 식사 45~75분이다. 실제 시설·필수 관람·프로그램·코스 식사·예약에 따라 조정하며 시간을 일괄 배수로 축소하거나 부풀리지 않는다. 첫날·마지막 날·대형 시설·종일 체험·장거리 이동은 실제 가용 시간에 맞춰 구성한다. 운영시간·필수 관람시간·예약·이동 여유·사용자 경계 시각을 우선한다.

예약·교통편·운영시간·실제 이동 여유로 설명되지 않는 60분 이상 공백과 근거 없이 긴 체류시간을 줄인다. 오후·저녁을 비운 조기 관광 종료와 18:00 복귀를 기본값으로 삼지 않는다. 주변의 의미 있는 볼거리는 동선과 이용 가능한 시간에 맞춰 검토하며, 숫자·공백 채우기 방문과 임의 휴식·대기는 생성하지 않는다.

여행 방식은 food(현지 식당·먹거리), highlights(대표 명소), cafes(실제 카페·사진 명소), culture(박물관·미술관·문화시설), shopping(시장·상점·쇼핑 거리), nature(공원·정원·해안·자연 경관 방문)를 장소 선정 우선순위로 반영한다. 복수 선택은 여행 전체에서 조합하되 모든 방식을 하루에 강제로 넣지 않는다. 맛집·카페 선호도 관광을 모두 식사로 대체하지 않으며, 자연·휴식도 독립 휴식·대기 활동을 만들지 않는다. 생성 화면의 선택지 설명도 같은 기준을 사용한다.

생성 흐름은 웹 검색 도구를 사용하는 AI 한 번 호출 → 장소 메타데이터 연결 → 결과 저장이다. 웹 검색을 필수 도구로 연결하고 시설별 여행 연도의 장기 휴업·공사·폐쇄를 우선 확인하도록 지시하되 서버 품질 판정이나 별도 AI 검토 호출은 추가하지 않는다. 전문 검토·통합 수정·자동 재시도 생성은 실행하지 않는다. 프롬프트는 여행 경계·확정 예약 → 실제 관광·식사 구성 → 운영시간·이동 가능성 확인 → 날짜별 시간표 완성 순서로 안내한다. 등록 장소가 없어도 실제 방문을 선정하며, 확인이 어려운 장소는 확인 가능한 대안으로 바꿔 시간표를 완성한다. 숙소·시작·종료 지점은 앱에서 연결한다. 이전 독립 활동 저장 구조는 기존 데이터·되돌리기 호환용으로 보존한다.

모델은 공식 시설·교통기관 자료를 우선해 방문 날짜의 운영·휴관·입장 마감·예약 필요 여부, 식당 위치·영업·휴게·마지막 주문을 웹 검색으로 확인한다. 이동은 현실적인 방문 순서·체류시간을 위한 여유로 고려하며 실제 구간 시간은 경로 API가 계산한다. 현지 요일과 시각, 관람·식사·이동 여유를 고려해 권역별로 묶고 불필요한 왕복을 줄이며 더 나은 대안으로 교체할 수 있다. 지정 숙소·시작/종료 조건과 확정 예약은 유지한다. 확인 결과는 방문 선택과 시간표 구성에 반영한다. 검증 근거·출처 URL·대안 변경 이유·제외 이유를 별도 필드로 생성하거나 저장하지 않으며, 미확인 정보나 예약 완료를 사실처럼 단정하지 않는다. 미래 운행·영업 및 실시간 경로를 보증하지 않는다. 날짜별 시간표는 숙소·공항 또는 사용자가 지정한 경계를 기준으로 계획하며 경계 표시는 앱의 기존 기능이 담당한다.

AI 응답은 `days: [{ date, visits: [...] }]` 하나의 날짜별 방문 시간표다. 등록·신규 장소를 같은 visits 배열에 넣으며, 방문은 savedPlaceId(새 장소는 null), placeName, regionName, startTime, durationMinutes, description, mealType을 가진다. 배열 순서가 그날의 방문 순서이며 서버가 기존 일정의 position으로 매핑한다. 한 방문은 지도에서 검색할 수 있는 실제 장소 한 곳이고 여러 명소나 대안을 한 항목에 묶지 않는다. 별도 placements·recommendations·unplaced·placeDescriptions·savedRecommendations·activities 및 reason·position·이동 필드는 AI 출력에 없다. 별도 보관함 추천은 생성하지 않고, 미방문 등록 장소는 삭제하지 않은 채 기존 보관함에 남긴다. 방문의 description은 장소 특징·볼거리·매력만 설명하며, 신규 장소 메모는 AI 추천 표식과 description을 저장한다. 기존 등록 장소의 메모가 비어 있으면 방문 설명으로 채우고 사용자 메모는 보존한다. 이전 활동 유형과 저장 구조는 기존 데이터·되돌리기 호환을 위해 유지하되 과거 활동 JSON의 제거된 필드는 API 반환·오프라인 되돌리기 요청에서 제외한다. 기존 장소 메모와 일정을 일괄 변경하지 않는다.

AI가 반환한 날짜 수·실제 방문 수·날짜별 방문 수는 output_received 로그에 기록한다. 장소 연결 단계는 visits_materialized에 매핑 방문 수·신규 장소 수·검색 실패 사유를 기록한다. completed 로그는 생성 대상 범위의 실제 저장 방문 수와 숙소 연결 항목 수를 구분하며, 숙소만 저장된 경우 실제 방문 수는 0으로 남긴다. 빈 일정도 서버 품질 검증이나 자동 재생성으로 거절하지 않으며 출력의 형식·참조·저장 무결성만 확인한다.

시작 시각은 입국·수하물 등 모든 수속이 끝나 실제 이동 가능한 시각이고 종료 시각은 공항 또는 지정 장소에 도착하는 목표 시각이다. 수속이나 수속 여유를 추가하지 않는다. 첫날은 시작 장소에서 첫 방문 장소로 바로 계획하며 숙소에 먼저 들르도록 강제하지 않는다.

호텔은 하루 출발·최종 도착 경계로 연결한다. 체크인·체크아웃·짐 보관·수령·객실 휴식·호텔 식사 등 호텔 내부 활동과 중간 호텔 방문 기록을 생성하지 않는다. 현실적인 숙소 중간 경유가 필요하면 계획의 이동 여유에 고려하되 별도 방문이나 경유 설명을 출력하지 않는다. 마지막 방문에서 호텔/종료 장소로 이동해 도착하면 일정을 끝내며 호텔 휴식 뒤 같은 호텔에 다시 도착하지 않는다. 모델이 임의로 휴식·대기·자유시간을 만들거나 카페/공원을 그 대체 방문으로 넣지 않는다. 교통 대기·환승은 이동시간 안에서 계산한다.

일정표와 지도는 방문 시각 대신 현재 position 순서를 따른다. 장소 카드 사이를 선으로 잇고 해당 구간 소요 분만 표시한다. 노선·교통수단·이동 제목·추정 설명·출처는 표시하지 않는다. 기존 AI 이동 활동과 방문에 저장된 이동시간은 화면의 소요시간에 사용하지 않는다. 이전 휴식·대기·호텔 활동은 화면·지도에 중간 장소로 삽입하거나 호텔 도착 시각에 더하지 않는다.

앱은 현재 순서의 인접 장소 쌍마다 경로 API를 호출한다. Google 환경에서는 Google Routes의 대중교통 소요시간을 사용하며, 숙소는 저장 장소 ID로, 여행의 시작·종료 경계는 해당 여행의 경계 참조로 조회한다. 서버는 여행 소유권과 장소 소속을 확인해 실제 Google 장소 ID를 해석한다. 알려진 현지 출발 시각(방문 시작+체류)은 여행지 시간대로 UTC 변환해 전달하고, 출발 시각을 모르면 공급자의 기본 시각을 사용한다. 일정 GET은 경로 조회를 기다리지 않고 저장된 장소를 반환한다.

DnD·장소 추가/제거·숙소 변경으로 인접 구간이 달라지면 새 구간을 조회한다. 요청 중에는 이전 시간을 숨기고 같은 자리에 작은 스피너를 표시하며, 실패·경로 없음은 확인 불가로 표시한다. AI 시간이나 임의의 0분으로 대체하지 않는다. 동일한 실제 장소인 경우에만 0분이다. 여행·날짜·방향·출발 시각·이동 모드·경계 위치 기준으로 진행 중 요청을 공유하고, 성공은 5분·실패는 15초 동안 재사용한다. 이전 순서의 응답이 늦게 도착해도 현재 구간을 덮어쓰지 않는다.

수동 변경은 구간 소요시간을 갱신하지만 방문 시작 시각·체류시간은 자동 변경하지 않는다. 방문 시각까지 재구성하려면 날짜별 AI 업데이트를 사용한다. 활동 JSON은 장소 목록과 같은 트랜잭션에서 저장하고, 날짜별 생성은 해당 날짜만 빈 활동으로 교체한다. 수동 저장의 activities 생략은 유지, 빈 배열은 제거를 뜻한다. AI 되돌리기는 장소와 이전 활동을 함께 복구하되 이전 이동 활동의 시간을 화면에 다시 사용하지 않는다. 기존 저장 일정은 자동 재생성하지 않는다.

서버는 관광·식사·영업시간·장소 유형·지역·동선·요청 충족 여부로 품질을 검사하거나 일정을 자동 보정하지 않는다. 권한·사용량·장소 소속·날짜 범위·저장 슬롯 등 저장 무결성 검사는 유지한다. 모델/API·응답 형식·저장 실패는 기술적 실패 사유를 기록하고 기존 일정을 유지한다. 웹 검색 생성은 스트리밍으로 진행 이벤트를 수신하며 기본 전체 제한은 10분, SDK 자동 재시도는 0회다. 전체 방문 일정을 반환할 기본 출력 예산은 64000토큰이며, 근거 설명과 반복 URL을 간결하게 작성한다. 출력 한도 초과는 output_limit으로 구분하고 응답 상태·설정 한도·실제 토큰 사용량을 기록한다. 전체 제한은 이벤트 수신 중에도 적용하고 초과하면 요청을 중단해 timeout 사유로 안내한다. 검색·작성 단계와 응답 ID·경과시간·완료 검색 수·마지막 이벤트 이후 시간을 generationId/tripId와 함께 기록한다. 사용자가 고정한 일정은 저장 시 보존한다.

장소 검색은 위치·사진 등 메타데이터 연결에만 사용한다. 검색 실패·결과 없음이어도 AI 방문을 유지하고 위치를 미상으로 둔다. 검색 후보를 지역·유형·식사 여부로 선별하지 않는다. 중복 Google 장소 엔티티는 재사용하되 여러 날짜의 방문 자체는 보존한다.

이미 저장된 일정은 자동 변경하지 않는다. AI가 추천한 새 장소는 기존 AI 추천 표시와 장소 메타데이터를 사용한다.

### 일정 편집의 날짜별 장소 선택

AI가 넣지 못한 장소는 삭제하지 않고 장소 보관함에 유지한다. 일정 편집 화면에는 별도의 전역 미배치 영역을 두지 않는다. 각 날짜의 `여행 장소 추가`에서 상세 선택 화면을 열고, 저장한 여행 장소를 체크해 해당 날짜에 넣는다.

날짜별 장소 선택 화면은 다음 두 탭을 제공한다.

- `미배치`: 아직 어느 날짜에도 배치하지 않은 장소만 보여주는 기본 탭
- `전체 장소`: 저장한 모든 여행 장소를 보여주며, 다른 날짜에 이미 배치한 장소도 반복 방문으로 추가할 수 있는 탭

미배치 이유 예시:

- 다른 장소와 이동 흐름이 맞지 않음
- 운영시간이 선택한 날짜와 충돌함
- 사용자가 선택한 순서와 함께 배치하기 어려움
- 여행 기간에 비해 저장 장소가 많음

같은 날짜에는 장소를 한 번만 선택하고, 다른 날짜에는 반복 배치할 수 있다. 사용자가 장소를 일정에 넣으면 필요에 따라 빠져야 하는 기존 일정 항목을 제안할 수 있다.

### AI 생성 횟수

다음은 AI 사용 1회로 계산한다.

- 최초 전체 일정 생성
- 전체 일정 다시 짜기
- 특정 날짜 다시 짜기

다음은 AI 사용 횟수에 포함하지 않는다.

- 드래그 앤 드롭
- 직접 추가 또는 삭제
- 단순 이동시간 재계산
- 운영시간 충돌 경고
- AI 변경안 비교
- 현재 화면에서 변경 직후 한 번 되돌리기

API 오류, 생성 실패 또는 생성 불가능 결과는 횟수를 차감하지 않는다. 정상 결과가 생성된 경우에만 차감한다.

## 12. 일정 편집

- 날짜 탭으로 하루의 지도·숙소·방문 일정을 상세 확인
- 드래그 앤 드롭으로 같은 날짜의 방문 순서 변경
- 좌우 드래그 앤 드롭으로 다른 날짜로 장소 이동
- 장소 추가 및 제거
- 같은 장소 반복 추가
- 이 날짜만 다시 짜기
- 전체 일정 다시 짜기
- AI 변경 전후 비교
- 적용 또는 취소
- 적용 직후 한 번 되돌리기

DB에는 최종 일정 한 버전만 저장한다. AI 변경안과 비교용 이전 상태는 임시로만 유지하며, 화면을 나가거나 새 변경을 시작하면 폐기한다.

운영시간이나 날짜별 종료 시간과 충돌해도 저장을 막지 않고 경고만 표시한다.

## 13. 지도와 길 찾기

### 앱 내부 지도

- 날짜별 장소 마커
- 방문 순서 번호
- 실제 좌표와 방문 순서를 연결한 동선
- 경로를 따라 움직이는 마커 애니메이션
- 같은 좌표의 시작·종료 숙소를 하나의 합성 마커로 표시
- 방문 일정의 장소를 누르면 해당 위치로 확대하고 장소 상세 표시

앱 내부 지도는 실제 내비게이션이 아니라 일정과 여정의 시각적 표현이다.
일정 카드 사이에 수동 대중교통 조회 버튼이나 Google Maps 외부 길 찾기 버튼을 두지 않는다.

### 여행 다시보기

위치 추적을 하지 않으므로 다시보기 경로는 실제 GPS 이동 경로가 아니다.

> 방문 순서를 기반으로 재구성한 여정입니다.

여행 완료 후에는 하나의 최종 여행 데이터만 남긴다. 다시보기에는 `평가 완료`와 `미평가` 방문을 포함하고 `미방문` 장소는 제외한다.

## 14. 여행 중 경험

여행 중에도 TripUS는 일정 확인과 관리에 집중한다.

### 제공

- 오늘의 일정 보기
- 날짜별 지도 동선과 방문 순서 확인
- 현장에서 발견한 장소 추가
- 사용자가 요청한 이후 동선 재계산
- 휴무 또는 날씨 문제에 대한 대체 장소 추천
- 오프라인 최소 일정 열람

### 제공하지 않음

- 실시간 방문 완료 또는 건너뛰기
- 자동 위치 추적
- 자동 도착 판정
- 백그라운드 지연 감지
- 자동 일정 변경

## 15. 여행 기록

### 방문 상태와 정리 방식

- 평가 완료: 방문했고 만족도 점수를 입력함
- 미평가: 방문한 것으로 처리하지만 점수가 없음
- 미방문: 방문하지 않음

사용자는 `평가 완료·미평가·미방문` 탭을 선택하지 않는다.

- 방문 장소에는 별점 1~5점을 선택적으로 입력한다.
- 별점을 입력하면 평가 완료, 별점 없이 정리를 완료하면 미평가로 결정된다.
- 미방문은 장소별 별도 버튼으로 지정하며 다시 방문 처리로 되돌릴 수 있다.
- 정리 없이 보관하면 일정에 포함된 장소를 모두 미평가로 처리한다.
- 여행을 완료하고 보관한 뒤에도 소유자는 사진, 별점과 후기를 추가하거나 수정할 수 있다. 수정 화면은 기존 기록을 먼저 불러오며, 사용자가 변경하지 않은 장소의 기록을 유지한다.

### 방문 기록 단위

각 방문은 고유한 `visitId`를 가지며 다음 정보로 구성한다.

- 여행 ID
- 날짜
- 장소
- 사용자가 입력한 방문 시간
- 방문 순서
- 방문 상태
- 만족도
- 후기
- 사진

계획과 다시보기에서는 반복 방문을 개별 일정 항목으로 유지한다. 여행 완료 정리에서는 같은 `savedPlaceId`를 한 번만 보여주며, 한 번 입력한 만족도·미방문 여부·후기를 같은 장소의 모든 일정 항목에 동일하게 반영한다. 사진 개수도 같은 장소의 일정 항목 전체를 합산한다.

### 추가 방문

계획에 없던 장소를 날짜별 최종 여행에 추가할 수 있다. 추가 방문도 일반 방문과 동일한 기록 구조를 사용한다.

## 16. 사진

### 기록 경험

- 완료 정리의 장소별 사진 첨부
- 대표 사진 선택
- 사용자가 선택한 방문 기록에 바로 사진 추가
- 업로드 중 상태는 해당 방문의 사진 영역 안에서 인라인으로 표시
- 여행의 시작·종료 지점은 이동 경계이며 방문 기록이 아니므로 사진·별점·후기와 미방문 처리 대상에서 제외한다.

사진 자동 분류 후보 화면과 사진 업로드 진행 전용 독립 화면은 제공하지 않는다.

### 메타데이터 정책

사진 자동 분류 후보를 제공하지 않으므로 촬영 날짜나 위치를 읽어 장소 연결을 제안하지 않는다.

- 사용자가 직접 선택한 원본 파일은 다운로드와 복구를 위해 비공개 저장소에 그대로 보존한다. 원본에 포함된 EXIF도 원본의 일부로 취급하며 공개 URL로 제공하지 않는다.
- 앱 표시용 최적화본과 썸네일은 이미지 방향을 실제 픽셀에 반영하고 GPS, 촬영일시, 기기정보 등 메타데이터를 복사하지 않는다.
- 사진 접근과 업로드는 사용자가 완료 정리 화면에서 명시적으로 선택한 때에만 수행한다.

### 저장

- 다운로드용 원본 이미지
- 앱 표시용 최적화 이미지

원본 사진은 사용자에게 저장 용량 한도를 두지 않는다. 서비스 운영을 위한 악용 방지·파일 단위 기술 제한은 별도 운영 정책으로 관리하되 Free/Plus 상품 차등 혜택으로 사용하지 않는다.

사진 삭제, 여행 삭제 또는 계정 탈퇴 시 원본과 최적화본을 삭제한다. CDN과 백업에서 최종 삭제되는 처리 기간은 약관과 개인정보처리방침에 명시한다.

업로드 실패 시 재시도를 제공하고, 네트워크 오류 중 작성한 후기는 기기에 임시 저장한다.

- 평가한 장소 수
- 지도 다시보기
- 해당 지역 방문 횟수

완성된 여행 상세에는 다음을 제공한다.

- 날짜별 타임라인
- 대표 사진
- 장소별 사진과 후기
- 만족도
- 총 이동 거리
- 방문 장소 수
- 방문 순서를 기반으로 재구성한 지도 애니메이션
- 사진, 별점과 후기 추가·수정 진입점

여행 캐러셀은 표지 뒤에 여행 시작일부터 종료일까지 날짜별 카드를 최대 두 장씩 구성한다. 첫 장은 요일·날짜·방문 시각·장소를 담은 일정표다. 방문 기록이 없는 날짜도 일정표 한 장은 만든다. 두 번째 장은 해당 날짜에 사용자가 등록한 사진이 있을 때만 만들며, 사진이 연결된 장소 중 별점이 가장 높은 장소의 사진과 장소명을 표시한다. 최고점이 같거나 모두 미평가이면 일정 순서상 첫 사진 장소를 선택한다. 인터넷 장소 사진은 사용하지 않는다. 날짜별 사진이 없으면 두 번째 장을 만들지 않는다. 전체 동선·3곳 단위 일정 분할·전체 베스트 모음 카드는 만들지 않는다. 모든 카드는 4:5 고정 영역의 안쪽 안전 여백을 지키고, 방문 수가 많으면 일정 행 간격과 장소명 줄 수를 줄여 영역 침범과 텍스트 잘림을 방지한다. 장소별 사진은 한 장만 등록할 수 있고, 등록된 사진은 여행 완료 정리 카드의 별점 위에 대표 이미지로 표시한다. 여행 기록 화면의 좌상단은 44×44 이상 터치 영역의 뒤로가기 아이콘이며 여행 작업 공간을 닫고 실제 진입했던 홈 또는 지난 여행 목록으로 돌아간다. 여행 제목은 본문에 표시한다. 캐러셀의 페이지 dot은 드래그·관성 스크롤 중에도 현재 위치에서 가장 가까운 페이지를 즉시 따라가며 양끝 바운스에서 범위를 벗어나지 않는다.

### 화면 탐색과 데이터 유지

홈·지난 여행·프로필은 기본 탭으로 유지한다. 목록에서 여행 또는 기록을 열면 기존 탭 위에 전체 화면의 여행 작업 공간이 오른쪽에서 들어온다. 닫으면 화면이 오른쪽으로 나가고 기존 탭과 스크롤 위치를 복원한다. 작업 공간 내부의 여행·장소·일정은 같은 스택에서 탐색하고, 여행 생성/수정·장소 추가·AI 입력·기록 편집·캐러셀 미리보기는 전체 화면으로 연다. 기존 경로와 딥링크를 유지하며 직접 진입 시에는 탭이 배경이 된다. 지도·DnD·미저장 편집과 충돌하지 않도록 작업 공간과 편집 화면의 제스처 닫기는 끈다. 미저장 변경은 이탈 확인으로 보호하고 저장·업로드·AI 처리 중에는 닫지 않는다.

서버 데이터는 React Query의 계정별 캐시를 공유한다. 최신 캐시가 있으면 화면 재진입 시 다시 호출하지 않고, 오래된 캐시를 갱신하는 동안에도 기존 목록을 유지한다. 수동 다시 시도는 강제 조회한다. 저장·완료 응답으로 관련 목록과 상세를 갱신하고 서버의 파생 결과만 재조회한다. 일정의 미저장 순서·메모는 조회 캐시와 분리해 보호한다.

## 23. 삭제

- 삭제 전 복구할 수 없다는 확인 문구를 표시한다.
- 사용자 화면에서는 삭제 후 복구할 수 없다.
- 여행 DB 행은 `active=false`로 비활성화한다.
- 비활성 여행은 무료 여행 개수에서 제외한다.
- 사진 원본과 최적화본은 실제 삭제한다.
- 후기 등 개인정보는 정해진 보존 기간 후 영구 삭제한다.
- 계정 탈퇴 시 개인정보를 제거한다.

서비스 내부의 soft delete와 개인정보·사진의 실제 삭제를 분리해서 처리한다.

## 27. 오류와 예외 처리

- AI 또는 API 오류는 무료 생성 횟수를 차감하지 않는다.
- 일정 충돌은 일정 편집의 정상적인 예외 화면으로 제공하며, 충돌 원인과 그대로 저장할 수 있음을 함께 보여준다.
- 대중교통 경로 계산 실패는 정상적인 예외 화면으로 제공하며 장소 순서를 유지하고 단순 연결선과 재시도 동작을 보여준다.
- Google 장소 정보를 찾을 수 없으면 계획 중 여행에서 읽기 전용으로 표시하고 삭제를 허용한다.
- 운영시간 충돌은 경고하되 저장을 차단하지 않는다.
- 하루 종료 시간보다 늦은 일정도 저장한다.
- 후기 작성 중 네트워크 오류가 발생하면 기기에 임시 저장한다.
- 사진 업로드 실패 시 개별 재시도를 제공한다.
- 삭제는 확인 절차를 거치며 사용자에게 복구 불가를 명확히 알린다.

여러 오류를 모은 `상태와 복구` 독립 화면은 제공하지 않는다. 예외는 발생한 기능의 화면 안에서 정상적인 분기 화면 또는 인라인 상태로 처리한다.

### 사진 메타데이터

> 사진의 촬영일시, 위치와 기기정보는 업로드 전에 제거되며 서버에 저장되지 않습니다.

### 삭제

> 여행을 삭제하면 복구할 수 없으며 등록한 사진과 기록도 함께 삭제됩니다.


### 홈 여행 카드 표지

- 진행 중인 여행 카드에는 첫 번째 선택 도시의 Google Places 사진을 자동 표지로 표시한다. 도시의 Google Place ID가 없으면 국가와 도시명으로 실제 도시를 조회한다.
- 사진 하단에 투명에서 짙어지는 그라데이션을 깔고 도시명과 여행 기간을 흰색으로 표시해 사진의 디테일과 글자 가독성을 함께 유지한다. 카드 아래의 Google Maps 출처·저작자 문구는 화면에 표시하지 않는다.
- 사진 조회·로딩 중, 사진 없음, 네트워크 오류에는 여행 ID로 고정한 일러스트·배경색 조합을 표시한다. 같은 여행의 조합은 다시 열어도 유지되며 서로 다른 여행도 조합이 겹칠 수 있다.
- 표지 조회는 여행 목록 조회와 분리하며 사진 실패가 목록 표시나 여행 열기를 차단하지 않는다. 짧은 수명의 사진 URL은 여행 데이터나 오프라인 캐시에 저장하지 않는다.
