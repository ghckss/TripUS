# 오프라인 캐시 검증 — 2026-11-27

## 목적

온라인에서 한 번 조회한 여행 기록과 실제 표시된 이미지가 앱 재실행 후 서버 API와 이미지 원본에 접근할 수 없는 상태에서도 기기 캐시로 복원되는지 확인한다.

## 환경

- iPhone 18 Pro 시뮬레이터, iOS 27.0
- TripUS Development Build와 최신 Metro 번들
- 테스트 계정의 완료 여행 `QA-Seoul-1124`
- 사용자 사진이 연결된 `광장시장` 기록

## 절차

1. 정상 API 설정으로 앱을 실행하고 완료 여행 기록을 연다.
2. 여행·일정·사진 목록 응답이 계정별 SQLite에 저장됐는지 확인한다.
3. `광장시장` 사용자 사진이 화면에 실제 렌더링돼 Expo Image 디스크 캐시에 기록되도록 한다.
4. 앱을 완전히 종료하고 SQLite 파일을 백업한다.
5. API 주소를 응답하지 않는 `127.0.0.1:9`로 바꾸고, 사진 목록의 원본·최적화·썸네일 URL도 같은 응답 불가 주소로 임시 변경한다. 사진 ID와 이미지 캐시 키는 유지한다.
6. 앱을 콜드 스타트하고 홈에서 여행 목록과 완료 여행 목록이 복원되는지 확인한다.
7. 같은 완료 여행 기록을 다시 열어 여행명·기간·장소·평가·통계와 사용자 사진이 표시되는지 확인한다.
8. 앱을 종료한 뒤 API 설정과 SQLite 파일을 백업본으로 복구하고 정상 설정으로 재실행한다.

| API 실패 콜드 스타트 | 성공 | 서버 응답 없이 홈의 진행 여행과 완료 여행 3건이 표시됨 |

## 범위와 한계

- 이 검증은 Mac 전체 네트워크를 끄지 않고 TripUS API와 대상 사진 원본만 결정적으로 차단한 서비스 격리 테스트다. 따라서 지도 타일 등 테스트 범위 밖의 인터넷 연결은 유지됐다.
- 한 번도 조회하지 않은 서버 데이터와 실제 렌더링되지 않은 이미지는 오프라인에서 새로 받을 수 없다.
- Google Places의 도시·장소 대표 사진은 공식 정책에 따라 디스크에 영속 저장하지 않으며 오프라인에서는 로컬 대체 이미지를 사용한다.
- OS 저장 공간 정리 또는 앱 삭제로 이미지 디스크 캐시가 제거된 경우에는 다시 온라인 다운로드가 필요하다.
- 실제 iOS·Android 기기의 비행기 모드, 네트워크 복구 직후 갱신, OS 강제 캐시 정리는 별도 출시 QA 대상으로 남긴다.
